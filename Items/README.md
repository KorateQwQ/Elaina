# 替换人物立绘与装备外观：绘制注意事项

修改人物身体、头部、帽子、腿部或整套外观替换时，先阅读本文。这里记录伊蕾娜遇到的实际问题，也可作为其他 tModLoader 替换人物贴图模组的排查参考。

本文依据本项目在 **2026-10-26** 使用的本机 tModLoader 源码与回归结果整理。迁移到其他版本或其他角色渲染器时，应重新核对入口和调用顺序。

## 1. 外观替换必须早于绘制状态准备

本项目曾出现这些现象：

- 正常游戏时看似正常，暂停后出现原装备的帽子、头发或遮挡残留。
- 穿星云头盔或整套星云装备时，角色脸部、帽子上出现紫色尖角，腿部也可能残留原装备发光。
- 主界面角色预览与游戏内表现不一致。

共同原因是替换时机太晚。原版并非在每个图层里都重新查询完整装备状态，而是先准备 `PlayerDrawSet`，计算头发显示、皮肤隐藏、发光遮罩、染色及复合手臂等数据，再交给图层绘制。

相关顺序可概括为：

```text
渲染入口
  → BoringSetup / HeadOnlySetup
  → ModifyDrawInfo
  → 各图层绘制
```

`DrawEffects` 位于完整人物的准备流程内部，但在它执行之前，一部分装备派生数据已经生成。此时或在 `ModifyDrawInfo` 中才改 `Player.head/body/legs`，就可能得到“伊蕾娜贴图 + 原装备派生状态”的混合结果。只清掉一个 `headGlowMask`，也无法覆盖其他早已生成的状态。

**不要依靠逐件屏蔽巫师帽、星云套等装备来解决这一类问题。先检查外观替换是否发生在准备流程之前。** 也不要仅依赖正常游戏更新中的外观设置：暂停、菜单预览和头像可能走不同的更新路径。

## 2. 每次绘制临时替换，并保证恢复

本项目实现见 [ElainaAppearanceSystem.cs](../System/ElainaAppearanceSystem.cs)：

- 在 `LegacyPlayerRenderer.DrawPlayer` 和 `DrawPlayerHead` 的原方法执行前设置伊蕾娜外观，分别覆盖完整人物与头像入口。
- 保存原来的 `head`、`body`、`legs`、`skinVariant`、`wearsRobe`，通过 `AppearanceScope` 临时替换。
- 整次绘制结束后恢复；使用 `using` / `try-finally`，确保异常和嵌套绘制也能正确恢复。
- 非伊蕾娜角色直接走原绘制流程。
- 不修改 `armor[]` 里的真实装备物品，不通过脱装备或改变装备属性实现外观替换。

原则是：

```text
保存原状态 → 设置角色外观 → 原版准备并绘制 → finally 恢复原状态
```

如果新增临时修改的字段，必须同时增加恢复逻辑。皮肤性别切换也需要关注 `skinVariant`，不能只记住一个“是否男性”的布尔值。

装备槽对应的 `ArmorIDs.*.Sets` 静态标记，应在内容初始化阶段配置。本项目在 `PostSetupContent` 中设置隐藏原版头部皮肤、身体皮肤和手臂等标记，不在每次绘制时改全局装备表。专用服务器跳过客户端绘制钩子与这部分初始化。

## 3. 绘制次数不等于游戏更新次数

同一角色可能因为阴影、头像、菜单、预览等在一帧内被绘制多次；游戏暂停后也仍会绘制。

- 动画计时、物品生成、伤害、材料消耗等逻辑应由游戏更新驱动。
- 不要仅用 `shadow == 0` 当作“本帧只执行一次”的保证。
- 不要在帽子或身体的 `Draw` 中无条件递减计时，否则暂停时也会继续动画。
- 不要在持续绘制睡眠姿势时反复播放入睡音效。

当前旧代码已为动作计数、帽子掉落计时、物品/变身生成和睡眠声增加暂停、菜单保护；这些保护不代表整个旧 `DrawEffects` 已完全无副作用。新增功能应直接采用更新计时、绘制只读的结构。

## 4. 图层父子关系与头像

- `AfterParent` / `BeforeParent` 的图层依赖父图层。隐藏父图层时，附属图层也可能一起不画。
- 如果替换完整人物并隐藏原版头部、手臂等图层，帽子、项链等仍需显示的自定义图层应检查是否也被父图层隐藏。
- 将附属图层改为独立 `Between` 图层后，需要核对原先由父图层提供的 `Transform`。例如 `TorsoGroup` 带来的躯干偏移不能漏算或重复计算。
- 独立帽子图层需要明确声明 `IsHeadLayer`，否则完整人物正常，头像中却可能没有帽子。
- `headOnlyRender` 应单独处理，避免把整个人物的脚底修正、炼金高度或倒重力偏移直接套在头像上。

## 5. 位置应以贴图实际边界与场景接触点校验

普通人物由多个装备图层组成，不能只查看一张身体 PNG 就判断脚底或头部正确。

本项目的鞋子画到了装备帧的最后一行，而原版装备绘制公式还有底部留白，导致普通立绘鞋底下沉。修正见 [ElainaDrawAlignment.cs](../System/ElainaDrawAlignment.cs)：只调整普通姿势的绘制位置和手持物绘制位置，保持实际坐标与碰撞箱不变。

**这里的 4 像素修正是当前贴图与绘制公式的实测结果，不是所有角色模组都该照抄的常量。** 坐骑、坐姿、睡眠、倒重力、死亡、变身、头像及完整帧动画可能已有自己的位置规则。

炼金的翻书、搅拌是完整人物帧图，与普通分层人物不同。它们的身体、帽子、项链和凳子使用统一基准；检查时除了脚底与凳面，还要检查棍尖与锅口等实际接触点。不要仅让脚底对上凳子，就认定整个动作高度正确。

正式绘制加载已有或离线制作的打包贴图。测试中可以临时生成辅助图，但不能把固定贴图的生成逻辑留在正式加载或绘制代码中。

## 6. 验证入口与最低覆盖范围

在仓库根目录运行：

```powershell
pwsh -File Tools/PlayerPosePreview/run.ps1
```

具体预览场景和结果说明见 [PlayerPosePreview/README.md](../Tools/PlayerPosePreview/README.md)。该工具调用真实的 `BoringSetup`、`HeadOnlySetup`、头部/腿部绘制，以及正式外观替换代码；光照和宿主环境使用隔离夹具。

本次应保留的回归范围：

- 正常游戏、暂停、主界面角色预览、头像。
- 巫师帽、仅星云头盔、星云整套；扫描其他原版头部装备槽，确认没有继承旧装备的发光或发型状态。
- 左右朝向、至少一个非整数缩放，以及受修改影响的坐骑、坐姿、倒重力、死亡等特殊姿势。
- 反复绘制不推进暂停计时；绘制前后的装备槽、皮肤与袍装标记一致；异常和嵌套调用也能恢复。
- 重新打开本次生成的图片检查，而不是只看编译和日志。

2026-10-26 的外观回归为 642 项断言，覆盖当时的全部 282 个原版头部装备槽。数量可能随工具或游戏版本变化，以当前脚本输出为准。离线通过后，仍需在重载模组后的实际游戏中验证暂停、菜单、饰品叠加及目标整合环境；不能据此承诺所有第三方渲染器都已兼容。
