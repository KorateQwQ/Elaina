# 冰水循环改版计划

> 2026-10-19更新：本文下方为历史设计记录。“冻结返还18秒/15秒间隔”已被一次性解封替代；水流返还冰凌锁CD改为0.30秒，冰锥积蓄5.6，冰凌锁按用户保存的250魔力/k1.06计算31.8B伤害。封印与60秒技能CD分别判断，冻结不重置CD，水系只推进CD不解封。成功施法重新封印；技能栏采用SkillBarSealPreview参考的原生动画，无解封浮字。当前行为与验证入口见Tools/IceCycleChecks/README.md、Tools/SkillBarPreview/README.md。暴雪首次习得条件不属于这次循环/封印改动。

日期：2026-10-16。用户已认可方向，本文记录第一版实施参数及验收目标。数值是试调起点，不代表已完成游戏实战或已保持最终 DPS 占比。

## 目标效果

- 冰锥、冰凌锁承担主要输出；水流负责持续辅助循环，水球负责补伤害、真空期输出和少量辅助。
- 开场已有一次冰凌锁，无需先冻结；冻结从爆发前置条件改为下一次爆发的冷却奖励。
- 冰凌锁本体提供高伤害，不读取、不消耗剩余冻结时间。
- 水系有效命中独立推进玩家的冰凌锁冷却，即使目标冻结 CD 为零、正在冻结或刚换阶段仍然有效。
- 理想稳定单体循环以约 28～32 秒一次冰凌锁为调参目标；实际受命中、施法占手、回蓝、急速和阶段无敌影响。
- 主要看技能栏的冰凌锁就绪状态；后续补冻结成功声音及技能栏切换提示，避免依赖敌人头顶小图标。

## 参数配置

伤害预算中的 B 指对应技能等级的基础 DPS，装备、暴击、防御及实际命中另算。不同技能等级的 B 可能不同，不能直接用这些倍率算全流程实战占比。

| 冰凌锁伤害 | 整次预算 21.2B；`k=1.7666666666666666`、`cdRatio=1`、`shots=1` | 保持原 JSON 的单次预算，延长 CD 不自动三倍增伤 |
| 冰凌锁索敌 | 必须选中鼠标附近的敌人；与冰锥共用准星和45帧动作；无目标不施法、不扣蓝/CD | 目标在施法时确定，之后不随鼠标换人 |
| 冰凌锁冰刺 | 15发，每发实际越过目标点时结算80像素半径AOE，合计分配整次预算的约50% | 当前轨迹首发第29帧、末发第96帧抵达，不依赖命中回调来触发动画事件 |

| 冰锥 | 每0.75秒3发、耗蓝4.5、DPS倍率0.9B，整轮预算0.675B | 保留本体输出与施法节奏 |

| 水流 | 每0.2秒1.5魔力；伤害参数不变：冻结CD期间0.9B DPS，否则0.7B | 持续辅助，保留现有输出条件 |

| 水球 | CD15秒、150魔力、k=1.5，基础预算6.75B；现有蓄水/大小倍率不变 | 补伤害和真空期输出；实际占手/伤害以现有动作和球大小为准 |
| 水球返还 | 每次施法命中：目标冻结CD减4秒，自身冰凌锁CD减3秒 | 一次明显辅助，不取代冰锥冻结奖励 |

`SkillBalance.json`保存伤害、耗蓝、基础冷却以及每技能独立的`freezeBuildup`。冰锥条目当前为2.8，冰凌锁为0，范围0..100，缺省0。技能在生成弹幕时复制本次配置，后续改配置不改变已发射弹幕。冻结条容量在KL中统一为100，仅表示进度刻度，不再全局规定每个冰技能需要几次命中。

单一技能持续命中的次数约为`ceil(100 / freezeBuildup)`；例如2.8→36次、5→20次、10→10次；0表示不积蓄，不应拿0作除数。不同技能混用时按点数共同推进，不按某一种技能的次数计数。每一发冰锥独立计点，多部位共享进度的规则保持。

冰元素伤害身份/飘字与冻结积蓄分开：冰命中tag只表示冰伤，不自动增加积蓄；命中拥有者提交本次攻击的点数，由服务器确认、累加并同步目标进度。冰凌锁0点命中不发积蓄请求，也不清除其他攻击已经积累的点数。未来冰技能通过通用`ConfigureFreezeBuildup`接入自己的配置；未配置来源默认0点。`IceCycleBalance.cs`仍保存循环返还、奖励间隔及爆发几何/时刻。

## 循环与边界

1. 开场冰锥/冰凌锁输出，无需等冻结图标。
2. 冰锥累计命中触发冻结，返还18秒冰凌锁冷却；冻结保留4秒控制。
3. 水流、水球继续补伤害并推进冰凌锁；目标解冻后，水系同时推进其冻结CD。
4. 冻结CD结束后再用冰锥积累下一次冻结；冰凌锁就绪即可按战斗窗口使用。

返还只扣当前剩余CD，最低0；就绪后不储存负CD，不额外攒层。转阶段不清玩家技能冷却或15秒奖励间隔，但真正新生NPC的冻结积蓄仍按KL现有规则重新开始。这里没有给新阶段免费充能。

水流按付费伤害周期去重；水球按同一弹幕/施法的直击与爆炸去重。同批攻击命中多少敌人，玩家只获得一次冰凌锁返还。各独立敌人可以分别减少其冻结CD，同一Boss元素锚点只减一次，不能把多个目标的减CD量相加返还玩家。

冻结奖励只归触发该次冻结的攻击者（常规循环为冰锥，其他玩家冰元素命中也遵循此规则）；玩家15秒间隔同时限制三发冰锥、多部位及不同小怪。已就绪时发生冻结也占用这次奖励间隔，避免把奖励预存到随后施法。KL在权威端实际施加冻结后发布事件，服务端使用本次StrikeNPC包已经记录的攻击者，不依赖客户端积蓄预测；未知来源不发奖。

冰凌锁每次伤害脉冲按共享血池去重，下一发重新允许命中；独立血池部件仍正常受到范围伤害。控制器、全部冰刺和拖尾使用同一个随目标平移的坐标系，尚未抵达前也持续跟随目标，鼠标移动不会改变已选目标。

2026-10-16按实战反馈追加独立「冰封」：控制由动画抵达事件直接施加，不依赖`OnHitNPC`，因此目标暂时伤害无敌、NPC命中免疫、debuff免疫均无法躲过控制。伤害本身仍服从正常防御、暴击、免伤/无敌规则；约50%指基础预算，防御和暴击可能改变实际最终占比。冰封不设置KL的冻结Buff、积蓄、逻辑冻结标志或冻结CD，也不会触发18秒冷却奖励。

控制锁住整个关联组的AI、位置、速度、朝向与动画帧，但保留正常Buff计时和伤害等更新。首次抵达前不提前控制，后续命中维持到终爆；新出现的关联部位加入控制。多个冰凌锁按玩家/弹幕身份分别持有控制，单次结束只解除自己的控制。

目标死亡、消失或NPC槽位复用时，解除本次冰封，但控制器不提前销毁：固定在最后跟随的位置，继续播放剩余冰刺动画、逐次AOE与最终爆炸，不重新锁定或控制溅射目标。脱离目标状态参与网络同步，不能因同槽位出现新敌人而恢复跟随。只有控制器自身被移除时终止剩余攻击并清理控制；另有有界超时防止残留。

## 伤害占比校准

当前源码此前有冰凌锁`CurrentCD<=1`与3点耗蓝测试覆盖，新视觉弹幕也未连接真实伤害，因此不能把该运行状态当作可靠的旧版DPS基准。21.2B是当前正式JSON预算，不是已验证的当前实战伤害。

第一版保持整次21.2B，固定长战、配装、技能等级与操作规则后，对比每技能实际伤害、平均释放间隔、耗蓝和过量伤害。若只校准冰凌锁自身平均DPS：

`新单次伤害 = 旧单次实际伤害 × 新平均释放间隔 / 旧平均释放间隔`

例：34秒一次变成30秒一次，单次需约为旧值88.2%。该公式不保证整体占比不变；仍需检查其他三个技能贡献。短战允许因开场爆发更强而改变占比，不应机械要求所有时长一致。

## 验收场景

检查开场有目标即可用、无目标拒绝；普通/冻结目标伤害预算相同且不消耗冻结；每发共享血池去重且下一发可再次伤害；15次小AOE＋一次终爆；伤害预算50/50及整数守恒；首发到达才冰封；暂时伤害无敌和debuff免疫不妨碍冰封；关联组完整控制、溅射敌人不受控制；终爆/销毁释放、多施法控制互不误删；NPC槽位复用不继承锁定；冻结系统无新增事件/冷却。原循环还需检查36次冻结、18秒奖励与15秒间隔、水系返还和多目标去重、就绪不攒返还等。
