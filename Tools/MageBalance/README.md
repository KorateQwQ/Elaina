## 使用与保存

### KL DPS 曲线自动同步

通过 `run.ps1` 启动的本地页面直接读取相邻 `KL/Utils/KLDpsHelper.cs` 的 `stateDps` 数组。以后只改这一个数组：打开页面、点击“重新读取”以及页面可见时每 2 秒检查都会更新各阶段伤害与逐级伤害预览，不需要重启页面服务。B 曲线不写入配置文件。KL 游戏代码仍需重新编译、加载后生效，这不是游戏 C# 热重载。

数组需保留 `float[] stateDps = [...]` 数值常量格式，支持注释、小数、科学计数法和 `f` 后缀。现有 19 个阶段加初始起点共 20 项；页面通过 B 反推等级，因此要求节点严格递增且在 1..1000000 内。缺文件或非法数组会明确显示同步失败并保留上次有效曲线，修正文件后自动恢复。

直接双击 HTML 打开时，浏览器不能读取旁边的 C# 文件，会使用注明的离线快照，**不自动同步 KL**。需要同步时使用 `run.ps1`。若已有旧版服务占用端口，启动脚本会提示重启或使用其他端口。

### 游戏内快捷配装

游戏中按 **L**（可在按键设置“打开快捷配装”中修改）打开快捷配装面板，仅伊蕾娜角色可用。左侧选择阶段（默认选中当前进度对应的阶段），右侧显示该阶段的护甲、饰品与属性，点击“一键换装”：

## 技能等级成长区间

2026-11-05 起，正式配置的所有输出条目设置 `growthStartLevel: 1`，首次解锁与成长节点分开。首次解锁仍遵循各技能的 Boss、材料、前置技能和探索条件；`unlockLevel` / `unlockStageCap` 不再赠送对应阶段的伤害。

- `growthStartLevel`：0 或省略时兼容旧节点，从 `unlockLevel` 起步；正整数（1–1000）使用独立成长起点。阶段成长的首段终点取起点所属的公共阶段上限。
- `growthMode: phase`：每阶段按 `levelsPerPhase` 开放升级。正式普攻节点为 1、3、5、8、10……；正式输出主动技能节点为 1、5、10、15……。
- `growthMode: interval`：从成长起点每隔 `levelInterval` 个角色等级开放一级。
- `maxLevel`：0 为不封顶，正数限制技能总级数。生活技能沿用旧成长节点与上限。

角色等级只限制可购买的最高技能等级。实际伤害使用已买到的技能等级映射出的基准；已有技能等级不自动增加，也不裁剪。比如假设冰凌锁在角色 Lv55 解锁，Lv1 的基准仍是角色 Lv1；可以立刻花点数购买十一阶升级到技能 Lv12，才得到角色 Lv55 的基准。55 只是回归案例，正式解锁条件未改成 55。

编辑器增加独立成长起点输入；选择解锁时期只更改解锁参数。读取、编辑、保存和重新加载保留成长起点及主动技能 DPS ratio。“各阶段伤害”表按解锁字段判断技能是否已解锁，不能用“成长节点从 1 开始”推断技能已经解锁。

普攻每阶进修 10 点，输出主动技能每阶 30 点，首次研习费用另计。预算、旧档退款和验证边界见 [等级重构验证记录](CombatProgression-2026-11-05.md)。

## 唯一配置格式

`basicAttacks`和`skills`的每个条目可配置`freezeBuildup`（0..100的小数，缺省0），表示每次有效命中增加的冻结点数，冻结条统一100点。当前冰锥5.6点、冰凌锁0点。该参数由技能复制到生成的弹幕上，不参与伤害定价；在“技能配置”页的“冻结积蓄”列编辑。

使用 `schema: elaina-mage-balance-v2`、`configuration.version: 2`。不再保留 `autoRatio`、`combat.autoCost`、`combat.autoInterval` 或 v1 兼容路径。

- `basicAttacks`：每项包括 `id`、`name`、`ratio`、`cost`、`interval`、`shots`、`unlockStageCap`、`unlockLevel`、`levelsPerPhase`，可选 `ratioCurve`。
- `maxLevel`：最高技能等级，0–1000 的整数；0 或省略表示不设固定上限。阶段成长与固定间隔成长都会在此等级停止，网页节点预览与游戏升级/伤害基准映射使用同一限制。配置页“技能等级成长区间”可直接编辑。炼金术正式配置为 8：角色等级 6、10、15、20、25、30、35、40 分别开放技能 Lv1–Lv8，困难模式角色达到 40 级后即可升满；后续进度不再开放 Lv9。伤害技能保持默认 0。
- `growthMode` / `levelInterval`：普攻与主动技能均支持，`growthMode` 为 `phase`（按阶段成长）或 `interval`（固定等级间隔），缺省为 `phase`；`levelInterval` 为 1–1000 的整数，缺省 5。固定间隔模式的第 N 级门槛为 `成长起点 + (N - 1) × levelInterval`；旧 v2 文件不含这些字段时保持原来的阶段成长，不需要手动迁移。
- `ratioCurve`：伤害系数随角色等级变化的曲线，格式 `[[等级, 系数], ...]`，最多 16 点，等级为 1–1000 的严格递增整数。普攻与配置了 `ratio` 的主动技能替代 DPS 倍率（0–5），其他主动技能替代 K（0–200）。节点之间线性插值，低于首点取首点、高于末点取末点；缺省、`null` 或空数组时使用固定 `ratio`。魔法飞弹默认 `[[1,1],[10,0.9],[20,0.8],[35,0.7],[50,0.6]]`：前期约 1.0B，Lv50 起收到 0.6B。
- `occupyRatio`：主动技能占手补偿倍率，缺省按 0 读取，范围 0–5。0 表示不补偿读条少打的普攻，伤害偏低的技能直接调高 `k`。单位是裸装基准 DPS B：1 表示每秒占手补 1 × B，不随所选参考普攻的倍率变化。
- `skills`：主动技能每项包括 `id`、`name`、`cost`、`cd`、`cdRatio`、`cast`、`k`、`shots`、`unlockStageCap`、`unlockLevel`、`levelsPerPhase`、`maxCharges`、`initialCharges`。`cdRatio` 缺省时按 1 读取，以兼容旧配置。`k` 范围 0–200；`maxCharges` 1–99，`initialCharges` 0–`maxCharges`。
- 普攻与主动技能的 `cost` 均可为小数（0–10000），游戏中特殊魔力按浮点扣除，技能面板显示最多两位小数。
- `costPercent`：主动技能可选，额外消耗最大特殊魔力的百分比（0–100，缺省 0），网页列名“+最大魔力%”。实际耗蓝 = `cost` + 最大魔力 × `costPercent`%，游戏每帧按当前魔力上限刷新，不参与伤害定价。多重射击为 `cost 3`、`costPercent 1`，以免后期魔力上限高时可近乎无限续射。
- 所有技能 ID 全局唯一。飞弹不是解析器特例，可以与其他技能一样修改/删除；至少保留一项普攻。
- `loadouts`：可选，18 项，第 i 项 `stage` 必须为 i；每项包括 `name`（1–64 字符）、`armor`、`slots`（5/6/7）、`items`（固定 7 项，每项 `id`、`prefix` 与旧版原版对照前缀 `vPrefix`；游戏端不读取，旧配置缺少时网页按默认值补齐）、`baseMana`（20–200，20 的倍数）、`maxLife`（100–500，400 以内为 20 的倍数，之后为 5 的倍数）。`armor`、饰品 `id`、`prefix` 使用网页内的键名（如 `jungle`、`sorcerer`、`arcane`），游戏端用 `ElainaModSkills/Loadout/LoadoutItems.cs` 映射到物品与前缀；新增键时两边同时修改，游戏端遇到未知键会跳过该项。
- `selectedBasicAttackId`：必须指向一项普攻（C# 解析要求）；页面自动维护，删除或改名普攻时跟随更新。
- 网页的阶段 B 与配装加成只用于预览；游戏用玩家真实等级限制升级，用技能实际等级映射伤害基准，并应用玩家实际装备。

## 定价

普攻：`整次基础伤害 = 等级基准B × ratio(等级) × interval`；`每发基础伤害 = 整次基础伤害 / shots`。`ratio(等级)` 在有 `ratioCurve` 时按曲线取值，否则为固定 `ratio`。游戏与网页都用技能等级映射出的角色等级取值。

例如 B=1000、固定 0.8B、0.5 秒、3 发：DPS=800，整次=400，每发≈133.33。耗蓝单独配置，不影响伤害。

主动：`整次基础伤害 = B × (occupyRatio × max(1/60, cast) + (rate / 100 / 20) × cost × cd × cdRatio × k)`。默认 `occupyRatio = 0`，读条期间少打的普攻不自动补偿，所以长读条技能（水球 cast 1、倾泻 cast 5）的 `k` 要相应调高。`cdRatio` 是 CD 伤害折算率，范围 0–1；它只影响由 CD 换算出的额外伤害，不改变实际 CD、充能或技能释放时机。默认 1（100%），功能型长 CD 技能可设为 0.25–0.75。`shots` 对整次预算做等额分摊，不改变整次总预算。

显式配置 `ratio` 的主动技能不走上式，按 DPS 直接定价：`整次基础伤害 = B × ratio × (cd + cast)`，即 DPS 以“CD + 读条”的完整循环计算为 `ratio × B`。每次释放实际要占用读条时长，因此周期计入 `cast`；如水球 `ratio 0.2、cd 10、cast 1` 整次为 2.2B。此时 `k`、`cdRatio`、`occupyRatio` 不参与伤害。

发数必须与实际命中设计一致，配置不会自动生成弹幕或改变动作。游戏伤害最终按整数处理，小伤害/大量分段可能有取整误差。范围、多目标、防御、命中率、暴击与实际动画不是基础预算的一部分。

## C# 统一读取

所有条目加载到 `SkillBalanceSystem.Current.Skills`，按 `SkillBalanceEntry.Kind` 区分定价公式，按 ID 查找，不按具体技能类分支。

### 在技能类内部：不传名称、玩家或伤害类型

飞弹、冰锥、水球都继承 `ElainaSkill`，使用同一套接口。父类默认按当前类名定位配置；网页的 ID 应与类名一致。配置存在时自动接入 `MaxLevel`，子类无需覆写；配置不存在时保留默认上限，特殊技能也可自行覆写 `MaxLevel` 或关闭 `UsesLiveBalance`。

```csharp
// 默认读取本技能的实际 Level，已经含装备增伤，不要再乘一次。
int damagePerProjectile = GetConfiguredDamage();
float baseDps = GetConfiguredDps(); // 基础周期 DPS，不含装备。

// 需要下一等级预览时显式指定；不修改已学习的 Level。
int nextDamage = GetConfiguredDamage(skillLevel: Level + 1);

// 需要耗蓝、周期和发数时，同样不指定名称。
if (!TryGetConfiguredBalance(out var balance))
    return;
int mana = balance.Entry.ManaCost;
double interval = balance.Entry.BaseCooldown;
int count = balance.HitCount;
int damage = balance.DamagePerHit;
int damageNode = balance.CharacterLevel; // 当前技能等级对应的伤害基准角色等级。
```

这两种取法选一种即可。默认按配置 `shots` 分摊；如果技能实际发数由代码确定，用 `GetConfiguredDamage(hitCount: actualCount)` 覆盖分摊数，不要在返回值上再除一次。未学习的技能实例默认按 Lv1 显示预览；底层查询显式传入 `skillLevel <= 0` 时不产生伤害。

### 在技能类外部：显式查询某个技能

只有工具、UI 或其他对象要查询某个技能时，才调用 `SkillBalanceSystem.TryGetPlayerBalance(player, skillId, skillLevel, damageClass, out var balance)`。这是上述实例接口的底层实现，不是冰锥专属用法；必须提供实际技能等级，玩家参数只提供装备增伤。

只看理论基础数值：`GetBaseDps(skillLevel, skillId)`、`GetBaseDamage(skillLevel, skillId)`。飞弹的静态 `GetDps(int)` / `GetDamage(int)` 参数也改为技能等级，不再是角色等级。主动技能的 DPS 是整次伤害除以 CD（显式 `ratio` 的技能除以 CD + 读条），包含 `occupyRatio` 占手部分（默认为 0），不是净额外 DPS。

当前飞弹、水球和冰锥都通过父类实例接口读取配置。冰锥按住左键持续引导，每 0.2 秒从角色身后随机位置发射一枚冰锥；冰锥不再锁定敌人。当前基础 DPS 系数为 1.8，每枚耗蓝 5。

## 加载边界

配置仅在本地读取，不参与联机同步。所有构建加载 `.tmod` 内配置；仅 `#if DEBUG` 构建每 0.5 秒热读取源码 JSON。Release 无文件轮询，修改后需重新打包并加载。错误文件保留上次有效快照；新值不回溯改变已生成弹幕和进行中的冷却。

### 飞行魔法 / 扫帚参数

`configuration.skills` 的 `FlightSkill` 行新增 `flight` 对象，直接编辑正式 JSON；网页导入/保存会完整保留该对象。`baseSpeed` 为基础速度，`learnedSpeedBonus` 为习得加成，`speedBonusPerLevel` 为每级追加加成；`boostMultiplier` / `boostManaPerSecond` 控制长按速度与每秒耗蓝，`holdSeconds` 是点按/长按阈值；`dashMultiplier` / `dashManaCost` / `dashSeconds` / `dashCooldownSeconds` 控制短冲刺；`handlingPercent` 为固定操控响应百分比（1–100，默认 25），每帧消除相应比例的当前速度与目标速度差，统一用于起步、转向和刹车，不随技能等级或药水成长；越高越跟手。旧的 `acceleration` / `braking` 已停用。时间均以秒表示，速度以像素/帧表示。普通飞行耗蓝固定为零，实际支付使用独特魔力且不转化生命。JSON 最大体积现为 64 KiB。

扫帚冲刺当前默认持续 **0.4 秒**；`flight.dashRecoverySeconds`（默认 **0.15 秒**）控制冲刺自然结束后的超速收回时间。其校验范围为 1/60–0.5 秒，仍使用固定的 `handlingPercent` 响应；冷却和一次性耗蓝不随恢复时间追加。
