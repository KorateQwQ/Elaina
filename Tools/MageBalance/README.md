# 法师配装成长实验室 · 通用技能配置 v2

## 使用与保存

打开 `index.html`。页面分为三个标签页：“平衡实验室”“配装与属性配置”和“技能等级成长区间”（地址带 `#loadouts` 或 `#progression` 时直接打开对应子页面，方向键可在标签间切换）。实验室自上而下为：共同基准、双方配装对比、DPS 结果与战斗续航模拟（含魔力时间轴）、普通攻击设计、主动技能设计（释放计划与魔力价值阶梯）；主动技能使用魔力转化定价。旧版的快速预算、预算公式区块已移除，数据来源列表保留在页面底部。技能等级成长区间已移至独立子页面，点击顶部同名标签即可编辑成长参数和查看逐级伤害，仍与实验室共用配置和保存入口。

- 双击 HTML：点击“保存到模组”，首次选择模组 `ElainaModSkills/Data/SkillBalance.json` 并授权，之后直接保存到同一文件。使用支持 File System Access 的 Chromium 浏览器；授权失效时再次授权。可点击配置文件信息旁的“更换…”重新选择；更换目标不会自动读取或写入。
- `run.ps1` 启动的本机服务页面：仍然可以直接保存固定路径，不需要选择文件。
- 主工具栏仅保留“保存到模组”“重新读取”和“更多”。重新读取会用文件内容替换页面参数，包括尚未写入的修改。
- “当前阶段”覆盖原版全流程 19 个时期（开局 → 月亮领主后），默认配装参考 terraria.wiki.gg 的 Guide:Class_setups 法师路线，数值取本地源码；第 k 个时期的基础 DPS 为 KL 表第 k 项（史莱姆王后 50、骷髅王后 200、双子后 450、世纪之花后 900、拜月后 1800、毕业 3500）。
- 切换阶段读取“配装与属性配置”页中该阶段的数据：两侧护甲、饰品、槽位数，伊蕾娜前缀（`prefix`）与原版对照前缀（`vPrefix`），基础魔力与最大生命，以及该阶段的基础 DPS；并把技能成长的预览角色等级设为该时期上限 5k：已解锁的主动技能全部启用，未解锁的停用；参考普攻未解锁时退回第一个已解锁的普攻。技能数值、普攻数值、战斗与资源设置都保留。实验室里的手动改动不会写回配装页。
- 伊蕾娜特殊魔力上限 = 基础魔力 + 装备魔力（护甲、饰品、奥秘）+ 伊蕾娜的帽子 20 + 灰之魔女 + 额外特殊魔力。“开启灰之魔女”默认勾选：超出 100 的最大生命只保留一半（向下取整），减少的生命上限按 1:1 转为特殊魔力上限（如 500 生命 → 保留 300，+200 魔力）。只按实验室“最大生命”（随阶段读取）计算，护甲、饰品额外提供的生命未计入，结果可能略低于游戏内。
- “更多 → 恢复默认…”需要确认，只重置页面（含全部阶段配装）及浏览器缓存，不自动写入模组文件。
- 不提供试算文件的导入／导出和结果下载；需要文件备份时直接复制配置 JSON。模组 JSON 含整份页面配置，游戏只读取需要的参数；不保存计算结果和战斗日志。文件选择、读取和写入失败时会显示原因，不误报保存成功。

## 配装与属性配置

左侧列出 19 个阶段，右侧编辑所选阶段的推荐配装与角色属性：

- 配装名称、护甲套装、饰品槽数量（5 / 6 专家 / 7 大师），7 个饰品，每个饰品分别设置伊蕾娜前缀与原版对照前缀（原版前缀只用于实验室对照，游戏换装只用伊蕾娜前缀）。超出槽数的饰品显示为灰色，不参与计算也不在游戏中装备。两组批量按钮（伊蕾娜：全奥秘／全增伤／全护佑／全无前缀；原版对照：全增伤／全护佑／全无前缀）设置本阶段已用槽位的前缀。
- 伊蕾娜的帽子（+10% 魔法伤害、+5 魔法暴击、+20 特殊魔力上限，不加原版魔力）作为全时期推荐饰品，默认占用每个阶段的第一个实际饰品槽。帽子只有伊蕾娜能装备：原版对照一侧留空（不计帽子属性或前缀），实验室原版饰品下拉框中也不提供。
- 默认按专家模式、扫帚承担机动、Boss 战兼顾输出与生存；开局为低资源起步，其后允许刷齐本阶段材料。起步木头盔＋紫晶长袍＋木护胫，史莱姆王后至肉前用丛林套；肉后／史莱姆皇后后用钛金法师套（精金世界可选精金法师套）；首只机械 Boss 后用神圣法师套；花后至月前完整输出幽灵套，月后星云套。精金法师头为 `AdamantiteHeadgear`（400），不是射手 `AdamantiteMask`（402）。
- 前期使用星力／魔力再生手环、再生手环、脚镣、鲨牙项链，世吞后加入蠕虫围巾，骷髅王后黑曜石护盾；肉后十字章护盾、神话护身符和巫师徽章，三王后才加入天界徽章；花后冰冻护盾，石巨人后天界壳／毁灭者徽章。围巾对应专家腐化路线，猩红可手动改混乱之脑。原版手铐的受伤回蓝不等于伊蕾娜特殊魔力回复，因此不再作为默认核心饰品。
- 数值来自当前 Terraria 1.4.4.9 实际程序集，获取门槛结合 Wiki 和本地源码；完整取舍、备选和来源见 [配装核对记录](LOADOUT-AUDIT.md)。网页不把幽灵追击、护盾、减伤、回复、穿甲等条件效果伪装成固定 DPS；这些因素也意味着不存在所有战斗条件下唯一最强的配装。
- 默认前缀按进度估计：哥布林工匠需要砸过暗影珠／猩红之心且有 200 生命才会来袭，之前只有找到／合成时的随机前缀。开局 0 条输出前缀，史莱姆王后 1 条（运气），克眼后 2 条，世吞／克脑后 3 条，蜂王后 4 条，骷髅王后起全部重铸；其余槽为“无前缀”（视为无用随机前缀，游戏换装时生成无前缀新物品）。伊蕾娜的输出前缀为奥秘，原版按本阶段护甲与饰品逐条选险恶或幸运。开局只有 3 件饰品、史莱姆王后 4 件，其余为空槽；专家模式血肉墙后（恶魔之心）起 6 槽。“全增伤”按本阶段护甲、饰品与实验室额外伤害／暴击，逐条选择让倍率 `(1 + 伤害%) × (1 + 暴击%)` 更高的险恶（+4% 伤害）或幸运（+4 暴击，暴击封顶 100%），打平取险恶；实验室两侧的“全增伤”同理。
- 基础魔力 20–200，按魔力水晶 20 一档；最大生命 100–500，400 以内按生命水晶 20 一档，之后按生命果 5 一档。输入其他值会就近取整。默认值按进度估计，例如史莱姆王后视为星星收集满、基础魔力 200；克苏鲁之眼后至少 200 生命（达到 200 生命才会触发来袭事件）。
- 下方统计显示装备伤害、暴击、特殊魔力上限（含帽子与灰之魔女）、前缀防御以及对应的生命水晶／生命果／魔力水晶数量；同一饰品重复装备时给出警告（游戏换装会跳过重复项）。
- “复制上一阶段”复制护甲、饰品、前缀与属性（保留名称）；“恢复本阶段默认”只重置当前阶段；“在实验室中查看”切到实验室并读取该阶段。
- 正在实验室中使用的阶段被编辑时，实验室同步更新配装、基础魔力与最大生命，但不重新执行技能解锁。

### 游戏内快捷配装

游戏中按 **L**（可在按键设置“打开快捷配装”中修改）打开快捷配装面板，仅伊蕾娜角色可用。左侧选择阶段（默认选中当前进度对应的阶段），右侧显示该阶段的护甲、饰品与属性，点击“一键换装”：

- 直接删除当前功能护甲与饰品（`armor[0..9]`，包括当前锁定的功能饰品槽），然后按预设顺序创建带指定前缀的新物品。背包不取用、不塞入旧装备，也不生成地面掉落。
- “无护甲”、法袍未指定的护腿、“空槽”和兼容旧 `utility` 键均清空对应槽位；重复／未知饰品不装备。未使用槽位不残留高阶段装备。
- 时装、染料、坐骑、背包以及其他配装栏不属于本次功能装备换装。缺少可用饰品槽时提示少装几件。
- 悬停物品格显示原版提示（含前缀属性）。
- 魔力水晶、生命水晶、生命果的使用数量直接设为该阶段的基础魔力与最大生命，可升可降（例如选“开局”可回到 100 血）。
- 只在单人模式下可用。配置来自加载的 `SkillBalance.json`，缺少 `loadouts` 时面板提示无配置。

旧网页缓存／文件读取时升级到 `loadoutRevision: 2`：完全匹配旧默认的阶段自动换为新默认，并同步未单独编辑的实验室装备；手动编辑过任一配装字段的阶段整体保留。最早的 `utility` 占位补齐仍兼容。需要覆盖自定义阶段时用“恢复本阶段默认”。

## 技能等级成长区间

在顶部同名子页面中，每个普攻／主动技能可独立选择成长方式：

- **按阶段成长**（默认）：沿用“完整阶段角色等级跨度”与“每阶段新增技能等级”，旧配置的节点不变。
- **固定等级间隔**：填写“每级角色等级间隔”（1–1000 的整数）；从“首级角色等级”起，每隔 N 个角色等级新增 1 个技能等级，不使用公共阶段跨度、解锁阶段上限或每阶段新增数量。例如角色 1 级解锁，间隔 10 → 1、11、21、31；间隔 7 → 1、8、15、22；角色 6 级解锁且间隔 7 → 6、13、20、27。解锁时期快捷选项仍会调整首级门槛与阶段标记，Boss 解锁规则不变。
- 切换成长方式保留另一种方式的参数，当前不使用的输入框会禁用。两种方式可以在不同技能上混用，网页预览和 C# 升级上限／伤害等级映射使用相同节点。

按阶段成长时，普通攻击与主动技能都可以独立配置：

- `unlockStageCap`：技能进入哪个角色阶段后开放。阶段跨度由 `progression.phaseSize` 控制，默认 5；飞弹默认 5，冰锥示例默认 10。
- `unlockLevel`：技能 Lv1 对应的角色等级。默认冰锥为 6，表示史莱姆王后的 6–10 级区间开始即可升到 Lv1；如果设计为必须满 10 级才解锁，把它改成 10。
- `levelsPerPhase`：每个完整角色阶段新增多少级，不包含解锁时获得的 Lv1。飞弹和冰锥默认都是 2。
- “解锁时期”下拉框是前两项的快捷写法：第 k 个时期（击败对应 Boss 后，KL 等级上限 5k）写入 `unlockStageCap = 5k`、`unlockLevel = 5k − 4`，例如史莱姆王后为 10 / 6。手填非 5 的倍数时显示“自定义”。时期不单独保存，C# 无需改动。

因此默认节点为：飞弹 `Lv1@角色1、Lv2@角色3、Lv3@角色5、Lv4@角色8、Lv5@角色10`；冰锥 `Lv1@角色6、Lv2@角色8、Lv3@角色10、Lv4@角色13、Lv5@角色15`。页面会按本地 KL 等级 DPS 曲线显示每级基准 B、整次伤害、每发伤害、整数取整结果和相对上一级提升，并标出当前预览角色等级能达到的技能等级。

C# 已自动接入这些节点：角色实际等级限制技能可升级上限；技能实际等级映射到节点对应的角色等级，再由 KL 曲线取得伤害基准 B。例如飞弹 Lv2 使用角色 3 级对应的 B，即使玩家已到角色 10 级，只要技能未升级，基础伤害就不变。装备增伤仍按玩家当前装备计算。

冰锥、风刃、水流术、火焰射线的首次习得额外检查角色等级上限是否达到各自 JSON 的 `unlockStageCap`。当前配置分别为冰锥 25（蜂王后）、风刃 20（世吞／克脑后）、水流术 30（骷髅王后）、火焰射线 40（血肉墙后）。不要求角色实际等级练到阶段上限；`unlockLevel` 仍用于首级伤害基准与成长节点。判断与本地化条件提示每次读取当前配置，默认材料／研习点消耗保留；这项接入只针对上述四个技能，不自动改变其他技能的解锁规则。

上限不会自动提升技能实际等级，也不会裁剪已有等级。首级角色门槛与 Boss 解锁条件仍需在解锁规则中判断；KL 的 `MaxLevel` 至少为 1，不能用它代替首次解锁判断。节点生成到角色 1000 级，超出节点范围的技能等级使用最后一个节点。

## 唯一配置格式

`basicAttacks`和`skills`的每个条目可配置`freezeBuildup`（0..100的小数，缺省0），表示每次有效命中增加的冻结点数，冻结条统一100点。当前冰锥2.8点（约36次命中）、冰凌锁0点。该参数由技能复制到生成的弹幕上，不参与DPS伤害预算；实验室重新读取/保存会保留该字段，目前通过JSON修改，静态DPS模拟不包含冻结积蓄或冰凌锁事件返还。

使用 `schema: elaina-mage-balance-v2`、`configuration.version: 2`。不再保留 `autoRatio`、`combat.autoCost`、`combat.autoInterval` 或 v1 兼容路径。

- `basicAttacks`：每项包括 `id`、`name`、`ratio`、`cost`、`interval`、`shots`、`unlockStageCap`、`unlockLevel`、`levelsPerPhase`，可选 `ratioCurve`。
- `maxLevel`：最高技能等级，0–1000 的整数；0 或省略表示不设固定上限。阶段成长与固定间隔成长都会在此等级停止，网页节点预览与游戏升级/伤害基准映射使用同一限制。配置页“技能等级成长区间”可直接编辑。炼金术正式配置为 8：角色等级 6、10、15、20、25、30、35、40 分别开放技能 Lv1–Lv8，困难模式角色达到 40 级后即可升满；后续进度不再开放 Lv9。伤害技能保持默认 0。
- `growthMode` / `levelInterval`：普攻与主动技能均支持，`growthMode` 为 `phase`（按阶段成长）或 `interval`（固定等级间隔），缺省为 `phase`；`levelInterval` 为 1–1000 的整数，缺省 5。固定间隔模式的第 N 级门槛为 `unlockLevel + (N - 1) × levelInterval`；旧 v2 文件不含这些字段时保持原来的阶段成长，不需要手动迁移。
- `ratioCurve`：普攻倍率随角色等级变化的曲线，格式 `[[等级, 倍率], ...]`，最多 16 点，等级为 1–1000 的严格递增整数，倍率 0–5。节点之间线性插值，低于首点取首点、高于末点取末点；缺省、`null` 或空数组时使用固定 `ratio`。魔法飞弹默认 `[[1,1],[10,0.9],[20,0.8],[35,0.7],[50,0.6]]`：前期约 1.0B，Lv50 起收到 0.6B。
- `occupyRatio`：主动技能占手补偿倍率，缺省按 0 读取，范围 0–5。0 表示不补偿读条少打的普攻，伤害偏低的技能直接调高 `k`。单位是裸装基准 DPS B：1 表示每秒占手补 1 × B，不随所选参考普攻的倍率变化。
- `skills`：主动技能每项包括 `id`、`name`、`cost`、`cd`、`cdRatio`、`cast`、`k`、`shots`、`unlockStageCap`、`unlockLevel`、`levelsPerPhase`，以及仅供网页模拟的启用、命中率、持续时间、充能等参数。`cdRatio` 缺省时按 1 读取，以兼容旧配置。`k` 范围 0–200；充能储存上限与开场次数 0–99（只用于网页模拟）。
- 普攻与主动技能的 `cost` 均可为小数（0–10000），游戏中特殊魔力按浮点扣除，技能面板显示最多两位小数。
- 所有技能 ID 全局唯一。飞弹不是解析器特例，可以与其他技能一样修改/删除；至少保留一项普攻。
- `stage`：实验室当前阶段（1–19），仅供网页恢复视图。
- `loadouts`：可选，19 项，第 i 项 `stage` 必须为 i；每项包括 `name`（1–64 字符）、`armor`、`slots`（5/6/7）、`items`（固定 7 项，每项 `id`、`prefix` 与网页专用的原版对照前缀 `vPrefix`；游戏端不读取 `vPrefix`，旧配置缺少时网页按默认值补齐）、`baseMana`（20–200，20 的倍数）、`maxLife`（100–500，400 以内为 20 的倍数，之后为 5 的倍数）。`armor`、饰品 `id`、`prefix` 使用网页内的键名（如 `jungle`、`sorcerer`、`arcane`），游戏端用 `ElainaModSkills/Loadout/LoadoutItems.cs` 映射到物品与前缀；新增键时两边同时修改，游戏端遇到未知键会跳过该项。
- `selectedBasicAttackId`：模拟中使用的普攻；不参与主动技能定价，也不会把所选普攻的参数覆盖到另一个技能 ID。
- 网页的阶段 B、配装和 `skillStats` 是试算数据；游戏用玩家真实等级限制升级，用技能实际等级映射伤害基准，并应用玩家实际装备。

## 定价

普攻：`整次基础伤害 = 等级基准B × ratio(等级) × interval`；`每发基础伤害 = 整次基础伤害 / shots`。`ratio(等级)` 在有 `ratioCurve` 时按曲线取值，否则为固定 `ratio`。游戏用技能等级映射出的角色等级取值；网页按当前 B 反推等级（如丛林 B=200 ≈ Lv30，倍率≈0.733；精金 B=450 = Lv50，倍率 0.6），普攻表下方的曲线图标出当前等级。

例如 B=1000、固定 0.8B、0.5 秒、3 发、整次耗蓝 10：DPS=800，整次=400，每发≈133.33，每秒耗蓝=20。

普攻表与参考普攻摘要显示 **每蓝价值** `ratio(等级) × interval / cost / (rate / 100 / 20)`，与技能每蓝价值采用相同的基础伤害单位；另显示 **每蓝伤害（当前配装）** `整次基础伤害 × 普攻装备倍率 / cost`，包含页面暴击期望。上例在 `rate=4` 时每蓝价值为 20，裸装每蓝伤害为 40。发数只分摊伤害，不改变每蓝价值。零耗蓝显示“无消耗”；`rate=0` 时归一化价值显示“—”，实际每蓝伤害仍可查看。技能表的每蓝净伤害还会扣除占手损失，并使用技能自身的装备继承设置。

主动：`整次基础伤害 = B × (occupyRatio × max(1/60, cast) + (rate / 100 / 20) × cost × cd × cdRatio × k)`。默认 `occupyRatio = 0`，读条期间少打的普攻不自动补偿，所以长读条技能（水球 cast 1、倾泻 cast 5）的 `k` 要相应调高；战斗模拟和魔力阶梯仍会扣除这部分普攻，得到真实净收益。`cdRatio` 是 CD 伤害折算率，范围 0–1；它只影响由 CD 换算出的额外伤害，不改变实际 CD、充能或技能释放时机。默认 1（100%），功能型长 CD 技能可设为 0.25–0.75。`shots` 对整次预算做等额分摊，不改变整次总预算。

发数必须与实际命中设计一致，配置不会自动生成弹幕或改变动作。游戏伤害最终按整数处理，小伤害/大量分段可能有取整误差。范围、多目标、防御、命中率、暴击与实际动画不是基础预算的一部分。网页沿用裸装 B 含基础暴击期望的口径；C# 返回的基础 DPS 不预乘暴击，不应把网页带装备的期望伤害直接作为弹幕 damage。


战斗模拟的释放策略包括按优先级、缺蓝攒蓝，以及“节约型”。节约型优先保证普通攻击：先预留普攻持续到战斗结束所需的魔力（`max(普攻单次耗蓝, (普攻每秒耗蓝 + 均匀受伤损蓝 − 回蓝) × 剩余时长 + 后续受伤事件)`），当前魔力加未用药剂超出这部分的余量才用于技能。技能按净性价比 `(整次伤害 × 命中率 − 参考普攻 DPS × 占手时长) ÷ 耗蓝` 从高到低释放，净收益不为正的技能不放，同效率时优先 CD 更长者。净回蓝为正时余量会继续增长，暂时付不起的高性价比技能（包括即将转好的）会占住预留；净回蓝不为正时余量不再增长，付不起的技能让给更便宜的技能。它只改变模拟释放顺序，不改变技能伤害、实际 CD 或耗蓝；超过魔力上限的无效技能不会阻止其他技能。药剂按满额计入余量，不扣除溢出浪费。

## 魔力价值阶梯（奥秘 vs 增伤参考）

战斗模拟结果下方的“魔力价值阶梯”用一个稳态近似解释“多出来的蓝去了哪里”，加技能、改数值前先看这里。页面内表头有悬停说明，下方术语表默认展开。

第一行是实测对比：把伊蕾娜所有已装备饰品（空槽除外）分别换成奥秘和增伤（逐条按当前伤害与暴击选险恶或幸运，并显示两者条数），其余配装、战斗设置和释放策略不变，各跑一次逐帧模拟，显示两者 DPS、相对原版的百分比、奥秘领先/落后的百分比以及平均每条的差距。差距小于 2% 时会提示结果容易被战斗条件翻转。这一对比不修改页面配装。

- **每蓝价值** `cd × cdRatio × k`：每花 1 点蓝换来的额外伤害（单位 `B × rate/100/20 × 技能倍率`）。占手时长不计入它；读条时少打的普攻（扣除占手补偿后）与命中率折损一起在“每蓝净伤害”中扣除。
- **蓝需求** `cost / cd`：按 CD 放满每秒要花的蓝。
- **技能可用蓝/秒** = 回蓝 − 普攻耗蓝 − 受伤损蓝 + (开场蓝 + 药剂) ÷ 战斗时长。
- **宽 / 窄**：蓝需求占技能可用蓝的比例。宽（≥ 50%）是蓄水池，奥秘多出来的蓝能继续转成伤害；窄（< 15%）很快放满，主要抬升两种配装的整体强度，不拉开差距；中间为“中”。
- **阶梯与边际技能**：把可用蓝按每蓝价值从高到低倒进技能，蓝用完的那一级是边际技能，奥秘多出来的蓝都按它的价值变成伤害。排在它之后的技能理论上分不到蓝；按优先级策略先放低价值技能会抢走高价值技能的蓝，此时它不如一个无消耗 buff。
- **盈亏线 V\*** = 增伤每条增加的 DPS（按当前配装再加一条险恶或幸运中收益更高者）÷ (奥秘每条增加的蓝/秒 × 单位伤害)。边际技能每蓝价值 ≥ V\* 时奥秘占优。实测略低于解析值（解析值偏保守）。
- **溢出**：全部技能放满仍有余蓝，多出的魔力不再变伤害，奥秘必然落后；需要加入宽且价值 ≥ V\* 的技能。
- **新增技能**：只有每蓝价值高于当前边际技能才会提高 DPS，增益约为 `(v − v边际) × 蓝需求`；高价值技能让蓝更紧缺，扩大奥秘的优势；单次蓝耗超过增伤配装魔力上限的技能只有奥秘能放。
- **局限**：稳态平均近似，不含开场爆发、CD 对齐、单次蓝耗门槛与受伤时机，以上方逐帧模拟为准。

## C# 统一读取

所有条目加载到 `SkillBalanceSystem.Current.Skills`，按 `SkillBalanceEntry.Kind` 区分定价公式，按 ID 查找，不按具体技能类分支。

### 在技能类内部：不传名称、玩家或伤害类型

飞弹、冰锥、水球都继承 `ElainaSkill`，使用同一套接口。父类默认按当前类名定位配置；网页的 ID 应与类名一致。配置存在时自动接入 `MaxLevel`，子类无需覆写；配置不存在时保留默认上限，特殊技能也可自行覆写 `MaxLevel` 或关闭 `UsesLiveBalance`。

```csharp
// 默认读取本技能的实际 Level，已经含装备增伤，不要再乘一次。
int damagePerProjectile = GetConfiguredDamage();
float baseDps = GetConfiguredDps(); // 基础周期 DPS，不含装备。

// 需要下一等级预览时显式指定；不修改已学习的 Level。
int nextDamage = GetConfiguredDamage(skillLevel: Level + 1);

// 需要耗蓝、周期和发数时，同样不指定名称。
if (!TryGetConfiguredBalance(out var balance))
    return;
int mana = balance.Entry.ManaCost;
double interval = balance.Entry.BaseCooldown;
int count = balance.HitCount;
int damage = balance.DamagePerHit;
int damageNode = balance.CharacterLevel; // 当前技能等级对应的伤害基准角色等级。
```

这两种取法选一种即可。默认按配置 `shots` 分摊；如果技能实际发数由代码确定，用 `GetConfiguredDamage(hitCount: actualCount)` 覆盖分摊数，不要在返回值上再除一次。未学习的技能实例默认按 Lv1 显示预览；底层查询显式传入 `skillLevel <= 0` 时不产生伤害。

### 在技能类外部：显式查询某个技能

只有工具、UI 或其他对象要查询某个技能时，才调用 `SkillBalanceSystem.TryGetPlayerBalance(player, skillId, skillLevel, damageClass, out var balance)`。这是上述实例接口的底层实现，不是冰锥专属用法；必须提供实际技能等级，玩家参数只提供装备增伤。

只看理论基础数值：`GetBaseDps(skillLevel, skillId)`、`GetBaseDamage(skillLevel, skillId)`。飞弹的静态 `GetDps(int)` / `GetDamage(int)` 参数也改为技能等级，不再是角色等级。主动技能的 DPS 是整次伤害除以 CD，包含 `occupyRatio` 占手部分（默认为 0），不是净额外 DPS。

当前飞弹、水球和冰锥都通过父类实例接口读取配置。冰锥保留原有三发生成位置和动作，按实际三发分摊伤害；网页 `IceConeSkill.shots` 也应设为 3，以使每发预览一致。此次未改变动作时长或弹幕运动。

## 加载边界

配置仅在本地读取，不参与联机同步。所有构建加载 `.tmod` 内配置；仅 `#if DEBUG` 构建每 0.5 秒热读取源码 JSON。Release 无文件轮询，修改后需重新打包并加载。错误文件保留上次有效快照；新值不回溯改变已生成弹幕和进行中的冷却。
