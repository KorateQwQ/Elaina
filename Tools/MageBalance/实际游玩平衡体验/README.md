# 实际游玩平衡体验

## 2026-10-27：前期伤害、风刃续航与水球爆发

本条依据玩家反馈、当前源码相对 Git HEAD 的差异、正式技能配置和本机已安装 `.tmod` 检查整理。玩家描述属于实战反馈；以下数值是代码计算与运行验证，不代表已经重新打过 Boss。

### 玩家反馈与调整目标

- 前期开荒伤害偏低，因此提高前几个成长节点的伤害基准。
- 风刃可以无限穿透敌人、穿墙且范围较大，玩家反馈几乎不掉蓝，持续按住即可横扫。目标是保留清群特色，降低输出效率并提高持续使用的资源成本。
- 水球在相应阶段习得后被反馈几乎可以秒杀肉山，因此下调单次爆发预算。
- 用户同时提到增加回蓝。需要区分：本次未提交差异实际包含的是**风刃耗蓝增加**；战斗回蓝源码和 Git HEAD 都已为 `10 + 最大独特魔力 × 2%/秒`，本轮未发现新的回蓝代码改动。页面的 `regenPercent=2.5` 是试算参数，不能当作游戏内回蓝配置。

### 实际数值与评价

#### 前期基础伤害

KL 的 `stateDps` 前六项变更如下；节点间线性插值。Lv0 只是计算起点。

| 对应角色等级 | 原基准 B | 新基准 B | 增幅 |
|---|---:|---:|---:|
| 0 | 20 | 30 | +50% |
| 5（史莱姆王前上限） | 30 | 50 | +66.7% |
| 10 | 50 | 70 | +40% |
| 15 | 80 | 100 | +25% |
| 20 | 110 | 130 | +18.2% |
| 25 | 150 | 160 | +6.7% |
| 30 及以后节点 | 保持原值 | 保持原值 | 0% |

Lv26–29 仍受 Lv25→30 插值影响。前期飞弹对应角色 Lv1、3、5 的 B 从 `22、26、30` 变为 `34、42、50`。这会增强所有使用这段 KL 基准的技能，不只飞弹。游戏按**已学习的技能等级映射出的角色等级节点**取 B，而非直接按玩家当前等级取 B。

评价：提升集中在前期，并逐步收敛，能直接改善初期伤害；但同一时间削弱风刃时，必须把这项普遍增伤一起计入。

#### 风刃：伤害倍率下调、耗蓝翻倍，但仍能持续施放

正式配置 `WindSlashSkill`：`ratio 0.5 → 0.4`，每次 `cost 2.5 → 5`，周期仍为 `0.4 秒`。在相同 B 下理论单目标 DPS 下降 20%，每秒耗蓝 `6.25 → 12.5`，每点魔力对应的伤害降为原来的 40%。

不过，新 KL 基准抵消了部分早期削弱：

| 技能对应角色节点 | 原理论 DPS | 新理论 DPS | 合并变更后降幅 | 裸装每发整数伤害 |
|---|---:|---:|---:|---|
| Lv16（风刃 Lv1） | 43 | 42.4 | −1.4% | 17 → 16 |
| Lv20 | 55 | 52 | −5.5% | 22 → 20 |
| Lv25 | 75 | 64 | −14.7% | 30 → 25 |
| Lv30 | 100 | 80 | −20% | 40 → 32 |

以上按配置周期、不计装备、暴击、防御与急速；理论 DPS 使用未取整伤害，每发整数伤害单列。

实际战斗回蓝为 `R = 10 + 0.02M`，其中 M 是最大独特魔力。风刃在无其他消耗、普通周期下，只要 `M ≥ 125`，平均回蓝就不低于每秒 12.5 的消耗。M=200 时每秒回 14，M=400 时每秒回 18。因此**耗蓝翻倍已接入，但“持续按住仍不掉蓝”的问题并未从机制上消除**。受伤、其他技能、急速和资源转化会改变实战收支；当前 `PostHurt` 内暂停回蓝的调用已被注释，不能默认受伤后会停回蓝三秒。

弹幕仍设定 `tileCollide=false`、`penetrate=-1`，每道风刃对同一个 NPC 只命中一次。无限穿透不同敌人和穿墙的优势保留，多目标收益不能用单目标 DPS 完整衡量。

评价：资源效率削弱明显，但初学阶段单目标伤害基本持平，且常见魔力上限下仍可自然续航。若目标是限制一直按住，需要进一步评估耗蓝与自然回复的关系，或调整群体收益、射程等；本记录不擅自追加调参。

#### 水球：爆发预算下降约三分之一，肉山仍需专项复测

`WaterBallSkill` 的 K 从 `2.25 → 1.5`，耗蓝 100、基准 CD 15 秒、CD 折算率 1、占手补偿 0 均未变化。当前 `rate=4`，整次基础伤害预算为：

`D = B × (4 / 100 / 20) × 100 × 15 × K`，即 `6.75B → 4.5B`。

| 技能对应角色节点 | 原整次基础预算 | 新整次基础预算 | 合并 KL 调整后降幅 |
|---|---:|---:|---:|
| Lv26（水球 Lv1） | 1080 | 756 | −30% |
| Lv30（水球 Lv2） | 1350 | 900 | −33.3% |
| Lv35（水球 Lv3，肉山前阶段上限） | 1687.5 | 1125 | −33.3% |

表中是裸装、未暴击、未减防的单目标基础预算；整数化在施加装备倍率后进行。水球技能把配置伤害传给 `Action_WaterBall`，再传给实际弹幕，未发现该路径仍使用旧的固定伤害。

水球死亡时会将穿透设为 −1，扩展范围并调用 `Projectile.Damage()`。肉山眼睛与本体共享生命，当前水球没有按共享生命主体统一限制直接伤害次数；现有 `IceWaterHitBatch` 的去重针对冰水循环效果，不是爆炸伤害。因此存在一次范围攻击命中多个部位、放大对肉山总伤害的风险。是否命中及具体次数取决于站位、飞行时间、碰撞与免疫状态，尚未通过实际战斗复现，不能直接宣称必定多倍伤害或已经解决秒杀。

评价：下调 K 的方向合理且数值链路有效，但仅降低单目标预算，不能替代对肉山共享生命多部位的命中检查。

### 改动是否已经生效

本次检查读取本机 `Mods/KL.tmod` 与 `Mods/伊蕾娜.tmod`，没有重新打包或覆盖它们。

| 项目 | 当前源码/正式 JSON | 已安装包检查结果 | 结论 |
|---|---|---|---|
| KL 前期基准 | `30,50,70,100,130,160,200` | 调用包内真实 DLL 得到 `20,30,50,80,110,150,200` | **新基准尚未进入已安装 KL 包**；需要重新构建 KL 并重载模组 |
| 风刃 | ratio=0.4、cost=5 | 包内 JSON 仍为 0.5、2.5 | 新配置未打包；开发模式有源码 JSON 热读取路径 |
| 水球 | K=1.5 | 包内 JSON 仍为 2.25 | 新配置未打包；开发模式有源码 JSON 热读取路径 |
| 游戏战斗回蓝 | `10 + 2%M` | 包内 DLL 的 getter 同为 10、0.02 | 当前回蓝规则已在包内，但不是页面的 5＋2.5% |

伊蕾娜已安装 DLL 包含 Debug 的 `Poll` 方法。该机制每约 0.5 秒检查 `Mod.SourceFolder` 下的正式 `SkillBalance.json`：路径有效且解析成功时，新施法伤害、耗蓝、后续冷却可更新；已经生成的弹幕和正在进行的冷却不会追溯改写。本次没有读取运行中游戏对象或复现施法，**只能确认热读取代码存在，不能证明玩家当前游戏会话已经读到了新 JSON**。Release 构建只读取包内配置。

尤其要避免出现“新技能 JSON＋旧 KL DLL”的混合版本：例如风刃 Lv1 的 B 仍为 86，水球 Lv1 的 B 仍为 160，其结果会与已读取新源码曲线的网页不同。复测前应重建 KL 与伊蕾娜并重新加载。

页面中的 `baseDps`、当前阶段、参考普攻及主动技能 `enabled=false` 是试算状态；水球未勾选不会把游戏中的水球禁用。`combat.regenPercent` 也没有进入游戏配置解析器。网页当前实际使用 `5 + 2.5%M`，M=200 时显示每秒 10，而游戏为 14；这会低估续航，需要统一口径后再据页面判断耗蓝压力。

### 验证证据与复测项

- `audit.py`：只读比较 Git HEAD、当前配置及已安装包；解出包内 JSON、调用真实 KL DLL 获取基准、读取伊蕾娜 DLL 回蓝 getter 和 Debug 热读取方法。结果保存在 [audit-results.json](audit-results.json)。
- `../test-runtime.cjs`：临时编译实际 `SkillBalanceConfig.cs`、`SkillBalanceSystem.cs`、`KLDpsHelper.cs`，验证当前配置的升级节点、伤害、取整、耗蓝、周期、装备倍率、热配置与错误保留；Debug 和 Release 各 36 项通过。测试已改为从 KL 当前源码读取曲线，避免拿 HTML 的离线快照作为新数值的期望值。
- 静态调用链核对：`ElainaSkill.ApplyBalanceConfiguration` → 风刃/水球 `PreUseSkill` 扣费 → `GetConfiguredDamage` → 实际弹幕。没有替代游戏内的命中、地形和联机测试。

在此目录运行 `python audit.py` 可重新生成检查结果；在上级目录运行 `node test-runtime.cjs` 可重跑 C# 验证。
