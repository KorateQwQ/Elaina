# 动态宝箱配方检查

运行 `pwsh -File Tools/AlchemyChestChecks/run.ps1`。编译正式模组（不打包、不覆盖安装的 tmod），然后引用编译产物和本机 tModLoader 程序集，使用隔离世界与角色对象验证。

- 止痛药 30% / 60% / 100%、轻羽 20% 起每次加 10 个百分点第 9 箱必出；成功开出即记为曾获得，后续固定 5%，不要求取走。
- 两张配方均检查留在箱中不拿、后续新箱的实际 5% 判定、不再累计保底、显迹尘使用降低后的概率、其他角色不受影响；检查未取走时的角色存读档，以及真实服务器开箱结果包在客户端恢复并保存该记录。
- 世界生成只登记、天然箱与后放箱的区分、重开去重、满箱、存档恢复、仅常春藤箱参与止痛药判定（其他箱型即使位于丛林也排除）、两张配方独立结算。
- 个人仓库、鼠标、地面拾取、实际人偶 `AddCargo`、已研究记录的获得判定。
- 真实 `MessageBuffer.GetData` 处理开箱请求，正式钩子执行抽取，只替换最终网络传输以捕获发送顺序；检查初始 40 槽包含配方，随后才通知客户端打开，无事后补发。
- 角色同步的发送者校验、重复初始化及较早服务器快照不能清掉本地刚获得的配方记录。
- 显迹尘提前取样并保存箱子的随机值，重复探测和存读档不会重抽；探测不结算保底，开箱沿用取样结果并按当时个人进度结算。旧候选箱存档缺少随机字段时按需补齐。
- 覆盖已存入配方、取走配方、满箱、箱子替换、区域范围、重叠去重、区域结束、角色死亡、世界清理、快照过期；截获真实 ModPacket 传输，确认只向区域拥有者发送，拒绝其他接收者和客户端上行的显示状态。

结果写入 `.vissandbox/alchemy-chest-checks`。不读取或修改任何真实角色/世界存档，也不替代完整游戏中两客户端与真实网络延迟的验收。
