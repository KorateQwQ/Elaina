# 回城魔法与占位特效

正式技能为 `ElainaModSkills/Skills/Recall/RecallSkill.cs`，使用已有 `RecallSkill.png`，按现有技能系统解锁、装备。目标选择与治疗一致：全世界没有其他存活同队非 PvP 友军时，左键直接以自己为目标施法；有友军但全部超出范围时，打开只显示自己的轮盘；有范围内友军时，显示自己和这些友军。轮盘中松开选中项确认，中心、右键或 Esc 取消。直接自选仍沿用生成端权威及服务器确认后扣费的流程。

目前默认消耗 200 魔力、冷却 10 秒；选人范围 3000 像素。阵法固定在确认目标当时的脚底，1.5 秒后把阵心 160 像素内、存活且同队非 PvP 的友军传送到所选友军的出生点，无有效床则退回世界出生点。双方都未选队伍也按同队处理。只在延迟结束时进行一次群体传送；此时走出阵法的人不传送，后来进入的人会参与。

联机时由施法客户端以自己的 `whoAmI` 生成起点弹幕，经原版 SyncProjectile 同步后向服务器登记。等待确认期间 `age = -1`，不可见、不蓄力、不扣费；登记获准后才通过原技能框架消耗魔力和层数，并开始蓄力。被拒绝、等待超时或确认时已不能施法会清理待确认弹幕并提示，不会先扣魔力。服务器在蓄力结束后通知原施法客户端生成出生地出口，出口 owner 仍是该施法玩家；服务器收到出口后才结算首次群体传送。网络往返会影响实际出现时间，但不会扣除 30 秒残留寿命。

激活时打开出生地出口，两端保留 30 秒。玩家靠近并将鼠标移到魔法阵椭圆上，右键单击即可免费往返，不检查魔力或技能冷却，也不要求拿着魔杖。每次传送有 45 帧防连触间隔，长按不重复触发。每名施法者最多维持一对门；确认有效的新施法后，立即关闭自己的上一对门（包括尚在蓄力的阵法），不影响其他玩家。取消选择或无效请求不会关闭旧门。目标在蓄力期间死亡、离线或换队则取消；施法者离线、任一端被销毁或世界卸载会清理通道。落点被封闭时寻找附近空位，找不到时不传送，不挖掘方块。

## 特效接手位置

- `RecallPortalProjectile.cs`：魔法阵弹幕，`PreDraw` 为绘制入口。`Projectile.Center` 是固定阵心。`ai[0]` 为配对 ID（需与 owner 联合使用），`ai[1]` 为总年龄帧数（-1 表示等待确认），`ai[2]` 为起点 0 / 出生地 1。90 帧进入激活阶段，1890 帧到期。延迟和残留时长的常量在 `RecallPortalSystem`。
- `RecallPortalDrawing.cs`：独立的占位绘制方法，紫色起点、蓝色出口，充能环、旋转六芒星与最后半秒淡出。替换此文件或 `PreDraw` 即可，不必修改传送逻辑。`Contains` 负责鼠标椭圆命中；更改形状时同步调整。
- `RecallPortalSystem.cs`：施法客户端生成、同步和销毁自己的两端法阵；服务器登记 `(owner, 配对 ID)`，校验请求者、目标、队伍、距离和通道，并计算安全落点、加载目的地区块及广播玩家传送。服务器不调用 NewProjectile 代替玩家生成法阵。首次消耗在获准回包后通过现有客户端技能框架执行，确认支付后服务器才启动通道，非新增反作弊系统。不同客户端可以使用相同数字 ID，配对、交互和关闭始终同时验证 owner。
- `RecallPortalPlayer.cs`：右键输入、防连触、换床同步。`ElainaSkillWheel` 在鼠标右键指向可用阵法时让出打开输入。

## 验证与重现

在模组根目录执行：

```powershell
& Tools/RecallPreview/run.ps1 -Checks
& Tools/RecallPreview/run.ps1
& Tools/HealingWheelPreview/check-behavior.ps1
python Tools/LocalizationChecks/check.py
dotnet build 伊蕾娜.csproj --no-restore -v quiet -t:Compile -p:BuildProjectReferences=false
```

回城行为检查直接链接正式技能、配对系统、玩家交互、弹幕和绘制源文件，104 项断言覆盖选择与取消、确认时失效、群体传送、统一床坐标、出生点回退、左右端往返、无二次消耗、精确到期、失效通道和右键输入。网络检查使用独立的两个客户端及专用服务器玩家/弹幕数组，服务器 `Main.myPlayer = 255`，严格模拟原版 NewProjectile 的 owner 判断（只有生成端为 owner 时才初始化 AI 并发送生成同步）。实际序列化的模组包交由正式 HandlePacket 处理，覆盖两端客户端生成、跨端同步、自选/队友、多人同编号隔离、重施关闭、拒绝/超时不扣费、重复回包、延迟确认与完整 30 秒寿命。引擎的 SyncProjectile/KillProjectile 转发、碰撞与轮盘宿主仍是适配桩，不等同于真实联机房间复测。

FNA 离线预览直接调用正式 `RecallPortalDrawing.Draw`，并通过 ContentManager 加载游戏安装中的 `Images/MagicPixel.xnb`（实际尺寸 1×1000），不再用自建 1×1 贴图替代法阵纹理。旧代码整图缩放会导致线宽放大 1000 倍，已使用原版资源复现满屏线条，再通过明确指定 1×1 源矩形修复。

预览包含 24 项实际渲染范围检查：六个时间点、1/1.5 倍缩放、PointClamp/LinearClamp，要求所有可见像素处于阵心附近，越界或完全不可见时失败并保存 `recall-bounds-failure.png`。隐藏窗口执行后退出，正常输出 `.vissandbox/recall-preview/recall-frames.png`。图中从左到右、从上到下为年龄 15 / 60 / 90 / 210 / 1800 / 1880 帧，前三格起点，后三格出口，第 4 格悬停；已打开检查修复后的输出。灰色人物是定位参考，预览不模拟真实地图、玩家外观、碰撞和网络。

源码以 `.cs.txt` 保存；生成工程在 `.vissandbox`，工具和预览产物不参与正式编译和模组打包。首次运行需要本机 .NET SDK、tModLoader FNA/native 库和 Terraria 的 Content 目录；可用 `-Tml` 与 `-TerrariaContent` 指定安装路径。编译命令关闭模组打包，允许游戏运行期间检查源码；应用到游戏需重新构建并加载模组。

仍需实际联机确认：两位玩家设置不同床后的群体回城、未加载地区的往返、床被拆除后的回退，以及不同延迟下的输入和出口寿命表现。
