# 火焰射线行为检查

2026-11-09：`DomainChecks.cs.txt` 使用当前正式 JSON 和实际伤害计算入口确认基础 DPS 系数为 0.5，自己的炎爆领域内额外加 0.2（当前为 0.7，即伤害提高 40%）；不改写 JSON。检查自己的/其他玩家的领域、出入范围、30 秒连续喷射、蓄力与松手、点燃与维持叠加、15 秒剩余时间上限、远端同步状态推进及到期移除。领域的 `ai[2]` 由拥有端维护，变化及维持期间每秒同步，远端按游戏 tick 推进；这不替代真实多人延迟测试。

快捷施法检查覆盖同帧双键、蓄力和喷射三个阶段，验证射线动作/token 保持、仅替换自己的领域、正式魔力/层数/CD 消耗、按住右键不连发、重新按下可重试，以及未学习/未装备/无层数/魔力不足/UI/失焦/聊天/菜单/死亡/受控/换物品/换技能/远端/松手/收势/射线消失时拒绝施法。夹具只替换弹幕生成边界，调用正式领域配置和 `OnSpawn`；不创建真实世界或玩家存档。

运行 `pwsh -NoProfile -File Tools/FireLaserChecks/run.ps1`。

只验证玩法链路时可设置环境变量 `FIRE_BEHAVIOR_CHECKS=1`，跳过 `CheckVisualCurves`，保留水面阻断和完整动作/魔力/冷却/同步检查。完整模式仍执行视觉断言；2026-11-02 的现有退场曲线在 `Line shrinks at least as fast as the head throughout release` 失败，行为模式的通过不代表该视觉断言通过。

脚本先编译模组，再使用实际 `Action_FireLaser`、`FireLaser`、`FireLaserSkill` 和 KL 动作/冷却系统检查：先蓄力（期间不扣魔、不造成伤害，松手直接结束并进入冷却）、爆开时首次结算、持续输出与耗魔、松手立即结束、结束后一秒才能重用，以及切换物品/技能、受控、死亡、UI 输入、弹幕消失、动作中断和魔力耗尽。额外检查远端不重复扣魔或造成伤害、动作 token 和周期参数的序列化。

FNA 宿主加载魔杖资源以构造正式动作；测试夹具提供玩家、弹幕实例和初始技能状态，不运行完整游戏的生成流程、命中结算、绘制或真实多人网络。输出及日志位于 `.vissandbox/fire-laser-checks`。

入退场额外检查：从零宽度展开、有限的爆发超调、24 tick 后精确恢复原宽度，并检查膨胀峰值至少保持 4 tick、退场只收缩直到完全消失，以及短/长射线和多个朝向的粒子始终从中心线独立随机分布并向两侧散开且数量有上限。视觉残影不延长伤害弹幕寿命，原有立即结束、耗魔、冷却及中断检查仍需全部通过。实际 Shader 消融与衔接由 `Tools/FireLaserPreview` 检查。

退场粒子必须同时沿射线正方向前进，且前向速度大于侧向速度；此断言能捕获旧版近乎垂直向两侧飞出的错误。

粒子专项：设置环境变量 FIRE_SPARK_CHECKS=1 后运行同一脚本，只检查本次粒子生成；覆盖多个朝向、长度和种子、复现性、非配对出生点、疏密间距、数量上限、长度差异和前向散开。该模式仍先编译正式模组，不执行入场曲线和动作行为检查。

水面阻断：直接调用正式 `FireLaser.WaterBlockDistance`，用虚拟液体表检查满格/半格水面、正反向与竖直/斜向射线、起点在水中、超出物块截断长度的水体被忽略。只有水阻挡，岩浆、蜂蜜等由正式的 `WaterAmountAt` 过滤（读取 `Main.tile`，本检查未覆盖）。
